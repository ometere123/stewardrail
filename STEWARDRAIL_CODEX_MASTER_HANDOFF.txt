Authority split:

- Vault: custody; exact one-time payout only after a terminal result reaches it
  from a protocol-FINALIZED court message.

CRITICAL FIT-5 PROPERTY
-----------------------
Do not turn this back into a single-principal wallet policy engine. The primary
use case is a shared treasury governed by multiple principals with potentially
conflicting incentives. No one principal has an allow/refuse override. Neutral
validator judgment is the trust boundary for ambiguous mandate compliance.

CRITICAL REVIEW GAPS THIS DESIGN MUST CLOSE
-------------------------------------------
1. Evidence authenticity, not only byte hashing:
   - frozen mandate authorizes issuer wallet + role + exact HTTPS origin;
   - issuer wallet attests exact charter + role + URI + SHA-256 on-chain;
   - validity is checked historically at spend request time;
   - leader and validators independently refetch and hash bytes.

2. Real appeal reversal:
   - prove ALLOW -> appeal REFUSE blocks payout;
   - prove REFUSE -> appeal ALLOW becomes payable;
   - appeal output becomes the effective decision, not merely a note/status.

3. Protocol finality:
   - Guard -> Court primary must use emit(on="finalized").
   - Court -> Vault terminal must use emit(on="finalized").
   - Vault must never infer finality from ACCEPTED or elapsed wall clock.
   - finalized-message handlers must remain idempotent and reject conflicts.

4. Source parity:
   - there is no second deployable representation.
   - contracts/SOURCE_MANIFEST.json must match the exact deployed files.
   - live proof packet must record all five SHA-256 values.
